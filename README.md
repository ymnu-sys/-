### 專題名稱

高科大智慧失物招領平台

### 專題背景

校園內經常有學生遺失或拾獲物品，但失物資訊分散在各社群平台，失主不容易找到物品。公開貼文常附上物品照片與細節，反而讓冒領者能照著描述領走物品。

### 專題目的

1. 集中各校區的拾獲物品資訊，讓失主可以瀏覽、搜尋與依類別篩選。
2. 將物品資訊分為「公開資訊」與「非公開驗證資訊」，只讓管理員看到驗證細節。
3. 透過認領申請、特徵比對、管理員人工審核與現場核對，降低冒領風險。
4. 以站內通知讓申請人掌握處理進度。

核心理念：**讓真正的失主容易找到物品，但不讓冒領者輕易取得認領所需的關鍵資訊。**

### 專題內容

| 角色 | 可以做的事 |
|---|---|
| 一般使用者（訪客） | 瀏覽、搜尋、篩選、查看公開物品資訊 |
| 拾獲者 | 登入後刊登拾獲物品，填寫公開資訊與非公開驗證特徵 |
| 認領者| 登入後提出認領申請、自行描述特徵、補充資料、查看進度與通知 |
| 管理員 | 查看非公開驗證特徵、核准／拒絕／要求補充、現場核對後確認完成領取、下架物品 |

主要功能：首頁、失物列表、搜尋與分類篩選、物品詳情、刊登拾獲物品、認領申請、管理員審核、認領狀態追蹤、站內通知。

認領狀態：`待審核` → `需要補充資料` / `審核通過` / `審核未通過`；`審核通過` 經現場核對後才會變成 `已完成領取`。

## 網站使用說明

### 技術

純 HTML + CSS + JavaScript（ES Modules），不使用框架，不需要安裝套件。資料使用瀏覽器 localStorage 與模擬資料。需要 Node.js 20 以上。

### 啟動方式

```powershell
npm start
```

開啟 <http://localhost:3000>。按 `Ctrl + C` 停止。

- ES Modules 不能直接雙擊 HTML 用 `file://` 開啟，請使用上述伺服器，或 VS Code 的 Live Server 擴充功能。
- 手機在同一個區網測試：`$env:HOST="0.0.0.0"; npm start`，再用手機開啟 `http://電腦IP:3000`。

### 測試

```powershell
npm test
```

手動測試清單見 [docs/TESTING.md](docs/TESTING.md)。

### 示範帳號（虛構）

| 帳號 | 密碼 | 身分 | 用途 |
|---|---|---|---|
| `student_a` | `demo1234` | 測試學生 A（DEMO0001） | 種子物品的拾獲者，示範刊登 |
| `student_b` | `demo1234` | 測試學生 B（DEMO0002） | 示範認領、補充資料、通知 |
| `admin` | `admin1234` | 示範管理員 | 審核、現場確認、物品管理 |

### 建議展示流程（約 5 分鐘）

1. 首頁 → 搜尋「短夾」→ 開啟詳情，說明哪些資訊不公開。
2. 搜尋「便條紙」得到 0 筆，說明隱藏特徵搜尋不到。
3. 點「我要認領」→ 登入 `student_b` → 填寫特徵送出。
4. 登出 → 登入 `admin` → 審核後台比對左右兩欄 → 要求補充資料。
5. 登入 `student_b` → 我的專區補充資料 → 查看通知。
6. 登入 `admin` → 核准 → 說明「審核通過 ≠ 已完成領取」→ 勾選現場核對 → 完成領取。
7. 登入 `student_a` → 刊登錢包，示範敏感照片警告與個資阻擋。
8. 頁尾「重置示範資料」恢復初始狀態。

### 安全與隱私規則（實作對照）

| # | 規則 | 實作 |
|---|---|---|
| 1 | 任何使用者都不能直接認領成功 | `createClaim` 只建立「待審核」 |
| 2 | 所有認領都必須經過管理員審核 | 狀態只能由 `transition` 改變 |
| 3 | 只有管理員可以核准或拒絕 | `applyTransition` 檢查 `role === "admin"` |
| 4 | 一般使用者不得查看非公開驗證資訊 | 驗證特徵存在 `lf_secrets`，只有 `getItemSecret(actor)` 可讀 |
| 5 | 公開頁面不顯示個人資料 | `toPublicItem` 白名單；`detectSensitiveText` 擋下號碼、Email、手機 |
| 6 | 照片不暴露敏感資料 | 敏感類別預設停用照片；壓縮重繪移除 EXIF |
| 7 | 公開搜尋不查詢隱藏資訊 | `searchPublicItems` 只比對公開欄位 |
| 8 | 審核通過後仍需現場確認 | 完成領取必須 `onsiteVerified: true` |
| 9 | 審核通過不等於已領回 | `APPROVED` 公開狀態仍為「認領處理中」 |
| 10 | 減少蒐集個資 | 認領只收姓名、學號、一個聯絡方式 |
| 11 | 不要求上傳證件照片 | 認領表單沒有檔案上傳 |
| 12 | 明確標示為課堂原型 | 每頁頂端橫幅、登入頁與後台警告 |
| 13 | 正式上線需改用伺服器端機制 | 見下方「原型限制」 |

### 原型限制（重要）

本網站是**課堂展示原型**，不具正式系統等級的資料保護與權限驗證：

- 所有資料（包含非公開驗證特徵）存在瀏覽器 localStorage，任何人用開發者工具都能查看或修改。
- 示範帳號密碼寫在前端程式中，角色檢查只在前端執行，可被繞過。
- 資料只存在單一瀏覽器，不同裝置之間不會同步。
- 照片以 base64 存入 localStorage，容量約 5MB。

若要正式上線，必須改為：

1. 伺服器端身分驗證（例如學校單一登入），密碼不可存在前端。
2. 伺服器端權限控管：驗證特徵與申請人資料只由後端 API 回傳給已驗證的管理員，並保留存取稽核紀錄。
3. 安全的資料庫儲存、HTTPS 傳輸、照片存放於受控的檔案服務。
4. 個資保存期限與刪除機制，符合個人資料保護法。
